# 005. サイト全体の地の配色

- 状態: 未決
- 起票日: 2026-08-22
- 関連: `scripts/build_site.py` の `STYLESHEET`
- 暫定実装: あり — 案A相当。地を宣言せず、端末のテーマ設定に任せている
- プレビュー: `python scripts/build_previews.py` を実行後、`site/previews/index.html` から

## 何に迷ったか

骨組みは地の色を一切宣言していない。`color-scheme: light dark` を置いてあるだけで、
背景も文字色も端末のテーマ設定そのままになっている。

これは判断を避けた結果であって、決めた結果ではない。
そして**この判断は他の提案より先に来るべきだった**。設計原則では地を単色に寄せてから
対比の強い色を意味に割り当てる（DP-7.2）、強調色は地の色相から十分離す（DP-7.6）と
しており、**地 → 差し色**の順で決まる。002（変動の配色）を先に決めたのは順序が逆だった。

実際に影響が出ている。002で選んだ下降の青 `#1f6feb` は白地で 4.63:1 とぎりぎり基準を満たすが、
**わずかに色味を入れた地（`#f6f8fb`）に置くと 4.36:1 に落ちて基準を割る**。
地を決めれば差し色も決まり直す、という依存が具体的な数値で現れている。

迷いの中身は、**識別と可読のどちらを取るか**ではなく、
**読み手のテーマ設定を尊重するか、こちらで見え方を固定するか**にある。

## 選択肢

| 案 | 内容 | 利点 | 欠点 |

| A | 無彩色のまま・端末のテーマに追従（現状） | どの環境でも破綻しない。実装も検証も最小 | サイトとしての識別が無い。素っ気なく、作りかけにも見える |

## 推奨案とその理由

**案B（色味のある地・端末のテーマに追従）を推す。**

案Cの見栄えは確かに良く、変動の赤と青も最も映える。ただし**読み手が明るい表示を選んでいるのに
暗い画面を返すのは、設定を無視すること**になる。毎日見る記録サイトで屋外や明るい室内での閲覧を
締め出す理由は乏しい。若年層向けの様式は、地を暗くしなくても差し色と字面で十分に作れる。

案Aを続ける手もあるが、これは「決めていない」状態の追認になる。
地が無彩色のままだと、002で選んだ色が地から浮いて見えるかを判断できず、
003（密度）でも罫線や縞の強さを決める基準が持てない。

案Bなら読み手の設定を尊重したまま識別が付き、明暗どちらでも意味の強弱が保たれる（DP-6.10）。
代償は明暗2種類ぶんの維持だが、既に002で両方を用意しており、増える負担は小さい。

なお案Bを採る場合、**002の下降色を `#1f6feb` から `#1a63d8` に変更する**必要がある。
色相はほぼ保ったまま明度だけ下げた値で、青灰の地で 5.17:1 を確保できる。

## 保留による影響範囲

決めないままでも壊れるものは無い。案A相当の状態が続く。

- 影響するのは `build_site.py` の `STYLESHEET` のみ。マークアップの変更は不要
- **002の決定に条件が付いたままになる。** 現在の下降色は白地を前提に選んだ値で、
  地に色味を入れると基準を割る。この提案が決まるまで002は完了しない
- **003（情報密度）が決められない。** 行を詰めたときの走査の補助（罫線か縞か、どの濃さか）は、
  地の明るさが決まらないと選べない（DP-4.3）
- **004（狭い画面での畳み方）にも影響する。** 1曲1ブロックに積み上げる案では
  ブロックの区切りを地との差で作るため、地が未定だと見え方を判断できない
- P8の個別曲ページ、P9の週次メールもこの決定を引き継ぐ。**サイト全体の基準になる**ため、
  後から変えると波及範囲が最も広い提案になる
- 逆にこれを先に決めれば、003・004の判断が安定する
