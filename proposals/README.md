# proposals

デザイン・UI・表示仕様のうち、**実装せずに判断を預けたもの**を1件1ファイルで置く場所。

作業のルールは [`../CLAUDE.md`](../CLAUDE.md) にある。要点だけ再掲する。

- 見え方が変わる判断に出会ったら、実装せずここに1枚書いて次のタスクへ進む
- データ層はここに来ない。テストが通れば承認なしで進める
- 承認を待つために作業全体を止めない

## 読む側の手順

1. 未決の提案を読む
2. 採る案を決めて、ファイル冒頭の `状態` を `採用（案B）` のように書き換える
3. 実装を依頼する。却下する場合は `状態: 却下` にして理由を1行足す

判断の履歴を残したいので、決まった提案も消さずに残す。

## 書式

`NNN-kebab-case-slug.md`。`NNN` は3桁の連番。[`TEMPLATE.md`](TEMPLATE.md) を写して使う。

必須の節は `## 何に迷ったか` `## 選択肢` `## 推奨案とその理由` `## 保留による影響範囲` の4つ。
`python scripts/check_proposals.py` で検査される（GitHub 上では `checks` ワークフロー）。
